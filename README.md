# Відлік до Барселони 🇺🇦 ✈️ 🇪🇸

Лендинг-відлік до переїзду з бекендом на Supabase: чек-лист, прогрес накопичень,
навчання, англійська, погода і цитата редагуються прямо на сайті і синхронізуються
в реальному часі між вами двома. Захищено спільним паролем.

- **Frontend:** Vite (vanilla JS) + SASS
- **Backend:** Supabase (Postgres + Realtime), без власного сервера
- **Хостинг:** GitHub Pages (деплой автоматичний через GitHub Actions)

---

## 1. Налаштування Supabase (один раз)

1. Зареєструйтесь на [supabase.com](https://supabase.com) → **New Project** (безкоштовний тариф достатньо).
2. Зачекайте, поки проєкт підніметься (1–2 хв).
3. Зайдіть у **SQL Editor** → **New query**, вставте туди весь вміст файлу
   [`supabase/schema.sql`](./supabase/schema.sql) з цього репозиторію і натисніть **Run**.
   Це створить таблиці, функції та початкові дані (ті, що зараз на макеті).
4. Там само в SQL Editor виконайте окремим запитом встановлення пароля
   (замініть на свій):
   ```sql
   select set_site_password('ваш_спільний_пароль');
   ```
   Цей пароль знатимете тільки ви двоє — саме він розблоковує редагування на сайті.
   Змінити пароль пізніше можна тим самим запитом з новим значенням.
5. Зайдіть у **Project Settings → API** і скопіюйте:
   - **Project URL** → це `VITE_SUPABASE_URL`
   - **anon public** ключ → це `VITE_SUPABASE_ANON_KEY`

   (Цей ключ публічний за задумом Supabase — він завжди потрапляє у фронтенд-код
   будь-якого сайту на Supabase. Захист даних забезпечують не він, а RLS-політики
   і перевірка пароля всередині функції `update_site_data`, які вже налаштовані
   в `schema.sql`.)

## 2. Локальний запуск

```bash
npm install
cp .env.example .env
# відкрийте .env і вставте VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY
npm run dev
```

Відкриється `http://localhost:5173`. Кнопка **«Увійти»** у шапці — вводите
спільний пароль, після цього з'являються олівці ✎ на картках і форма
додавання пунктів у чек-листі. Пароль запам'ятовується в браузері, тож
вводити його доведеться лише один раз на кожному пристрої.

## 3. Деплой на GitHub Pages

### 3.1. Створіть репозиторій і запуште код

```bash
git init
git add .
git commit -m "Countdown to Barcelona"
git branch -M main
git remote add origin https://github.com/<ваш-username>/<назва-репо>.git
git push -u origin main
```

### 3.2. Вкажіть назву репозиторію у `vite.config.js`

Відкрийте `vite.config.js` і замініть:

```js
const GH_PAGES_BASE = '/countdown-to-barcelona/';
```

на

```js
const GH_PAGES_BASE = '/<назва-вашого-репо>/';
```

(зі слешем на початку і в кінці). Якщо сайт буде на `<username>.github.io`
(user/organization page, без підпапки) — залиште просто `'/'`.

### 3.3. Додайте секрети в GitHub

У репозиторії: **Settings → Secrets and variables → Actions → New repository secret**,
додайте два секрети:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

(значення ті самі, що й у вашому локальному `.env`)

### 3.4. Увімкніть GitHub Pages

**Settings → Pages → Build and deployment → Source** → виберіть **GitHub Actions**.

### 3.5. Задеплойте

Просто запуште будь-який коміт у `main` — workflow
[`.github/workflows/deploy.yml`](./.github/workflows/deploy.yml) збере проєкт
і опублікує його автоматично. Прогрес можна дивитись у вкладці **Actions**.
Через хвилину-дві сайт буде доступний за адресою
`https://<username>.github.io/<назва-репо>/`.

## 4. Що можна редагувати на сайті

Після входу за паролем (натисніть 🔒 **Увійти** у шапці):

| Блок | Що редагується |
|---|---|
| Маршрут і дата | Звідки/куди, дата вильоту (відлік перерахується автоматично) |
| Чек-лист переїзду | Додавання (поле внизу списку), видалення (× при наведенні), відмітка виконано |
| Прогрес накопичень | Поточна сума, ціль |
| GoIT Fullstack | Відсоток прогресу, технології |
| Рівень англійської | Поточний рівень, ціль, відсоток |
| Погода | Температура, опис, вологість, вітер, відчувається як |
| Цитата | Текст внизу сторінки |

Зміни зберігаються в Supabase і за 1–2 секунди з'являються у другого партнера
без перезавантаження сторінки (Supabase Realtime).

## 6. Безпека — що варто розуміти

- Пароль ніколи не зберігається у відкритому вигляді — у базі лежить лише
  bcrypt-хеш (`crypt()` з `pgcrypto`), а перевірка відбувається всередині
  Postgres-функції на боці Supabase.
- Прямий запис у таблицю `site_data` через API заборонено (RLS дозволяє тільки
  читання). Єдиний шлях щось змінити — функція `update_site_data(pwd, data)`,
  яка спершу звіряє пароль і лише тоді записує.
- Це достатній захист для приватного сайту на двох людей, але не є
  промисловим рівнем безпеки (наприклад, немає обмеження на кількість спроб
  введення пароля). Для цього проєкту цього більш ніж достатньо.
- Якщо захочете, щоб замість спільного пароля у кожного був окремий логін —
  можна замінити цю систему на Supabase Auth (email+пароль на кожного) —
  напишіть, і ми це додамо.
